    Abstract

    AI coding assistants can generate frontend code quickly, but speed does not guarantee that the resulting interface follows the engineering standards a team depends on. Accessibility, testing, component consistency, and maintainability can easily become issues that engineers discover only after the code has already been generated. This talk explores how platform engineering principles can be applied to AI-assisted frontend development. Using accessibility as a practical example, I’ll show how reusable components, design-system constraints, automated testing, Storybook, Playwright, axe-core, and CI checks can create a paved path that guides both developers and AI coding tools toward better implementations. We’ll compare three approaches: relying on AI-generated code as-is, adding standards through prompting, and enforcing engineering expectations through architecture-level guardrails. I’ll also cover where these guardrails help, where they fall short, and what teams should consider as AI-generated code becomes a larger part of everyday development. Attendees will leave with practical ideas for evolving developer platforms so that AI-generated code follows more of the same standards expected from human-written code.
