# Your AI Kill Switch Is Probably Broken

A talk at [Conf42 Feature Flags 2026](https://www.conf42.com/featureflags2026) by [Parthiban Rajasekaran](https://www.conf42.com/speaker_Parthiban_Rajasekaran) (Principal Dev Engineer @ Capital One). Page: https://www.conf42.com/Feature_Flags_2026_Parthiban_Rajasekaran_ai_kill_switch

Video: https://www.youtube.com/watch?v=ptOND07GfnU

## Abstract

Your autonomous agent starts making the wrong production calls.  You flip the kill switch.  The dashboard says Disabled.  Thirty seconds later, tool calls are still being executed.  Why?  Because changing a feature flag can stop new work without terminating work that is already in flight.  Most feature flags are admission controls. A real kill switch also needs cancellation semantics.  Feature flags are increasingly being used to control models, prompts, tools, routing, and agent behaviour at runtime. But autonomous systems introduce failure modes that ordinary feature toggles were never designed to solve: active tool executions that never re-evaluate the flag, stale provider state during connectivity failures, asynchronous workers operating from cached configuration, and fallback paths that have not seen production traffic in months.  In this 15-minute lightning talk, I will stage an automated Kill-Switch Fire Drill against a running agent loop and show three things:  1. The Admission-Control Trap: why disabling the flag blocks new agent runs while existing executions continue. 2. The Stale-State Trap: how cached state and provider failover can leave different workers with different views of whether the agent is actually enabled. 3. The Containment Proof: how to combine flag-evaluation events with OpenTelemetry and assert that active runs and tool calls reach zero within a defined containment SLO.  We will encode the expected behaviour in a small machine-readable Kill-Switch Contract, then deliberately flip the flag and prove whether the system actually obeys it.  I will also show the failure modes teams usually discover too late: fail-open defaults, stale fallback paths, partial shutdown, and an agent that still has access to the same control plane intended to contain it.  The takeaway is simple:  A flag value is intent. Containment is something you have to prove.  If your kill switch has never been exercised, do not wait for an AI incident to discover what it really switches off.
