# Kubernetes Scaling for Savings and Stability:  Beyond HPA and VPA

A talk at [Conf42 Observability 2026](https://www.conf42.com/obs2026) by [Joshua Fox](https://www.conf42.com/speaker_Joshua_Fox) (Senior Cloud Archtiect @ DoiT International). Page: https://www.conf42.com/Observability_2026_Joshua_Fox_kubernetes_autoscaling_reliability

## Abstract

**The Challenge with Standard Autoscaling** Site Reliability Engineers battle the tension between application reliability and resource bloat. Standard Kubernetes autoscalers rely on broad, shallow metrics like average CPU usage, forcing teams to make coarse and wasteful guesses. This leads to some challenges. 1. **Delayed Decisions:** Simple averages mask the true performance profile of complex applications. 2. **HPA/VPA Conflict:** Independent scaling tools collide, issuing contradictory instructions and causing scaling thrash. 3. **Eviction-Based Resizing:** Legacy VPA requires disruptive pod evictions, increasing cold-start latency for stateful or cache-sensitive workloads. **The Multi-Layered Observability Stack** This session explores how to build smarter, proactive scaling with a rich, multi-dimensional observability pipeline. We will show how to capture and use fine-grained signals across four key layers: * **Container Telemetry (cAdvisor):** Capture micro-burst latency, CPU CFS throttling, and memory working sets, which prevents errant scaling based on benign page cache growth. * **Cluster State (Kube-State-Metrics):** Gain crucial context on workload health, pending replicas, and HPA saturation to ensure scaling is necessary and not already in progress. * **Deep Application Signals (eBPF):** Probe the kernel to surface internal application metrics, such as JVM heap allocation rates and Garbage Collection (GC) pressure. This enables preemptive resource adjustments before OOM events even occur. * **Hardware Accelerators (NVIDIA DCGM):** Detect and scale based on GPU bottlenecks, such as SM utilization or memory bandwidth saturation. **From Insight to Action: The Unified Controller** Observability is only as valuable as the actions it enables. We will demonstrate how to build a unified controller that aggregates the telemetry layers into a state machine. By weighting different application signals and validating cluster state, the controller arbitrates between horizontal and vertical scaling, eliminating HPA/VPA conflict. We will show how to feed this multi-dimensional telemetry directly into the Kubernetes **InPlacePodVerticalScaling API**. Attendees will leave with the blueprints for translating deep observability directly into cluster optimization—mutating CPU and memory allocations on the fly without dropped connections or pod restarts.
