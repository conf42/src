# Self-Optimizing Infrastructure: Putting AI Inside the SDLC at 200K Requests per Second

A talk at [Conf42 Feature Flags 2026](https://www.conf42.com/featureflags2026) by [Naveen Goel](https://www.conf42.com/speaker_Naveen_Goel) (Senior Program Manager @ Amazon). Page: https://www.conf42.com/Feature_Flags_2026_Naveen_Goel_infrastructure_ai_sdlc

Video: https://www.youtube.com/watch?v=vz6vGSsSMpc

## Abstract

Most teams treat AI in operations as a dashboard — something a human checks after the damage is done. At the scale of a connected-device fleet serving 200,000+ requests per second across tens of thousands of servers, that model has already failed: the operational data outpaces human analysis, and a quiet 15% CPU regression in a hot-path API becomes a fleet-sized capacity bill before anyone opens a graph.  This session makes the case for AI as an operator rather than an observer, and walks through the closed loop that makes it work: performance-aware code review at development time, payload replay and resource-signature profiling in CI, phased canary→cell→region deployment, baseline-learned anomaly detection that correlates a code or payload change to a CPU/memory/IO spike, and a remediation agent that proposes and applies a fix — then re-proves it through the same phased pipeline before the system trusts it.  We'll cover the guardrails that make autonomous action safe in production: contained blast radius, reversibility, logged and reviewable actions, and where the human stays in the loop for high-stakes calls. Drawn from running service operations for a large-scale consumer IoT platform, where reliability isn't an SLA credit — it's whether the camera at someone's front door is working.
