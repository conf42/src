# Surviving Kubernetes Failures: HA Database Design and Chaos Testing

A talk at [Conf42 Chaos Engineering 2026](https://www.conf42.com/chaos2026) by [Mayank Gupta](https://www.conf42.com/speaker_Mayank_Gupta) (Senior R&D Engineer @ Broadcom). Page: https://www.conf42.com/Chaos_Engineering_2026_Mayank_Gupta_kubernetes_database_ha

## Abstract

Infrastructure failures are inevitable, but database outages do not have to result in prolonged service disruptions. As organizations deploy mission-critical databases on private Kubernetes clouds, maintaining availability during node failures, storage disruptions, and network outages becomes essential. Stateful workloads introduce complex challenges involving replication, failover, data consistency, and recovery.  This session explores practical strategies for designing and validating highly available database platforms on Kubernetes. Attendees will learn how synchronous and asynchronous replication, automated failover, resilient storage, and Kubernetes-native orchestration can improve database reliability during infrastructure failures.  The discussion examines StatefulSets, TiDB Operator, AlloyDB Omni Kubernetes Operator, PostgreSQL with Patroni and pg_auto_failover, MySQL Group Replication, and MariaDB Enterprise Operator. It also covers storage-class selection, resource management, network considerations, and Pod Disruption Budgets for maintaining service continuity.  A key focus is chaos engineering through controlled failure testing and gameday exercises. By simulating node failures, zonal outages, and network disruptions, teams can identify weaknesses, evaluate recovery procedures, and validate high availability strategies.  Participants will gain a practical framework for strengthening database resilience, improving recovery readiness, and maintaining reliable Kubernetes database operations.
