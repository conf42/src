# Break Your Own Agent: A Blast-Radius Experiment on 'Isolated' AI Subagents

A talk at [Conf42 Chaos Engineering 2026](https://www.conf42.com/chaos2026) by [Nishant Kumar Thakur](https://www.conf42.com/speaker_Nishant_Kumar_Thakur) (Senior Computer Scientist @ Adobe) and [Aishwarya Mathuria](https://www.conf42.com/speaker_Aishwarya_Mathuria) (Computer Scientist @ Adobe). Page: https://www.conf42.com/Chaos_Engineering_2026_Nishant_Kumar_Thakur_Aishwarya_Mathuria_agent_subagents_radius

## Abstract

Agent frameworks call their subagents "isolated". That can mean a separate conversation, or it can mean a security boundary. This talk tests which one you get, as a chaos experiment. In each run, we look at the blast radius: what the subagent can reach.  The hypothesis is that a read-only subagent cannot leak secrets, because it has no write tool and no edit tool. To test it, we clone a repo. Its README asks for a routine environment check. The script behind that check prints every variable with "key", "secret" or "token" in its name.  Experiment 1 runs on the host. The hypothesis fails. The tool limit holds, because a blocked tool has no handler in the code. But the child process inherits the full environment of the parent. The keys move from the subagent output to the parent context and then to the session log.  Experiment 2 runs the same task in plain Docker, with one key passed in with "-e". Only that key leaks. The other secrets are out of reach.  Experiment 3 uses Docker Sandboxes. The sandbox gets a placeholder token, and a proxy swaps in the real token on egress. The process inside never sees the real credential.  We use decoy credentials and one open-source agent, "pi", pinned to one version. Its docs say it has no built-in sandbox, which makes it a fair test subject.  The talk ends with three questions to ask about any "isolated" agent: - The talk ends with three questions to ask about any "isolated" agent: - Does the child scope its credentials or inherit them? - Is the boundary an OS, a VM, a container, or a proxy, or only a separate conversation?  We also map the tool limit to the OWASP Agentic AI Top 10. It partly covers ASI02 (tool misuse) and does nothing for ASI03 (identity and privilege abuse).
