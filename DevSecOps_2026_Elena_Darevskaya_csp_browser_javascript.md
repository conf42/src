# When Working JavaScript Breaks: Browser Security Policies in Practice

A talk at [Conf42 DevSecOps 2026](https://www.conf42.com/devsecops2026) by [Elena Darevskaya](https://www.conf42.com/speaker_Elena_Darevskaya) (Senior Platform Engineer @ SAP). Page: https://www.conf42.com/DevSecOps_2026_Elena_Darevskaya_csp_browser_javascript

Video: https://www.youtube.com/watch?v=OD1T6D9jhqo

## Abstract

In this talk, we will examine how browser security policies break JavaScript execution and leave with concrete strategies for catching and fixing these issues early in development. We'll start with live demos of how browser security policies break common JavaScript patterns, then look at ways to catch these issues earlier.  It is based on my real life experience working on a web SDK that customers embed into their site: code that worked correctly in my environment would suddenly break once added into a customer's site, because they used different security headers, like Content Security Policy (CSP) or Cross-Origin-Opener-Policy (COOP).  We’ll look at demos of how browser security policies block eval and blob-based resources, change the way iframe can communicate with parent windows, and break popups.  Once we've seen how these policies break things, we'll look at how to catch these issues earlier in development. Checking source code and build output can help us find capabilities that will be blocked by security headers, automated testing - demonstrate how our code actually works under browser constraints, and report-only policies - try out security headers without breaking our sites.  The goal is to help developers treat security policies as part of the development process and catch possible issues earlier.
