# Your SBOM Stops at the model

A talk at [Conf42 DevSecOps 2026](https://www.conf42.com/devsecops2026) by [Emmy Eide](https://www.conf42.com/speaker_Emmy_Eide) (Engineering & Cybersecurity Lead @ Realign Labs). Page: https://www.conf42.com/DevSecOps_2026_Emmy_Eide_sbom_models_supplychain

Video: https://www.youtube.com/watch?v=i1ULxAbM_pE

## Abstract

DevSecOps got good at a specific problem: proving what is in the artifact. Scan it, sign it, generate an SBOM, gate the pipeline on provenance. That entire apparatus assumes the artifact is code you can read.  Then the artifact started carrying weights. A model-bearing service ships a multi-gigabyte binary blob that no scanner parses, that no SBOM format meaningfully describes, and whose behavior is not a function of its source. This talk is about the specific places a working DevSecOps pipeline goes quiet when an agent moves through it. I will cover which gates still fire, which ones pass an artifact they cannot actually inspect, and what a security engineer should ask for instead. When I keynoted CloudNativeSecurityCon in 2023, the number I put on the stage was six of every seven: six of every seven project vulnerabilities are inherited from dependencies nobody on the team wrote. This is the first one you cannot read at all.
