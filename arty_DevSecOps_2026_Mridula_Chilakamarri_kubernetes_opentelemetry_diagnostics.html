    Abstract

    Distributed enterprise platforms running on Kubernetes can make request failures difficult to diagnose when telemetry is fragmented across services, logs, metrics, and tracing systems. This session presents a practical approach to building deterministic request-level diagnostics using OpenTelemetry and the W3C Trace Context standard. Rather than treating observability as isolated instrumentation work, the session examines the architecture and engineering decisions required to make request tracing reliable, secure, and operationally useful across independently deployed microservices. The approach combines ingress-level trace identity, mandatory context propagation, allowlist-based metadata, configuration-driven telemetry controls, and non-disruptive handling of telemetry failures. The session draws on a production enterprise platform to explain implementation lessons, including how architectural constraints, security requirements, and failure scenarios shaped the final design. It introduces seven independently testable evaluation criteria for verifying tracing completeness and operational readiness, while capturing nine approved operational trace metadata fields through an allowlist model. The design maintains zero request impact when telemetry components fail and supports enterprise compliance requirements including SOC 2, HIPAA, and PCI-DSS. Attendees will gain practical techniques for debugging distributed Kubernetes systems, improving observability reliability, reducing diagnostic friction, and integrating security and resilience into DevSecOps workflows.
