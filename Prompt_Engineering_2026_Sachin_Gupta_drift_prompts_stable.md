# Prompt Drift Kills: How to Make Prompts Stable

A talk at [Conf42 Prompt Engineering 2026](https://www.conf42.com/prompt2026) by [Sachin Gupta](https://www.conf42.com/speaker_Sachin_Gupta) (Member Of Technical Staff - 2 @ eBay). Page: https://www.conf42.com/Prompt_Engineering_2026_Sachin_Gupta_drift_prompts_stable

Video: https://www.youtube.com/watch?v=c-ms45Ab_vs

## Abstract

Most prompt engineering guidance is intuition, but production teams need prompts that behave like software artifacts: versioned, testable, and resistant to drift. A small prompt edit or model change can break output structure, increase hallucinations, or blow up token budgets, and you only notice after users complain. This talk presents prompt contracts: a method that turns prompts into enforceable specifications using structured outputs, explicit invariants, and automated tests. We will define contract clauses such as required fields, banned claims, citation rules, and token ceilings, then enforce them with JSON schema validation plus a small suite of golden tests and fuzz tests. I will demo a real regression caused by a harmless prompt tweak, show how CI catches it, and fix it by tightening the contract and examples. The implementation uses Java for the application path and a lightweight Python harness for test execution, so teams can adopt it without changing their stack.
