    Abstract

    A better answer score does not prove that an AI agent completed its task. Learn how to evaluate tool-using agents through observable actions and outcomes, and turn those checks into release decisions for code, prompt and model changes.

    An agent can produce a convincing completion message while a tool request remains unresolved, an action has been repeated, or a required approval was missing. A text-only evaluation can reward the response while overlooking the execution failure. Conversely, an agent that refuses every action is not a reliable system simply because it avoids unsafe effects.

    Drawing on Sajal Garg’s work on automated LLM evaluation infrastructure at Microsoft AI, this session develops an evaluation workflow around a non-confidential illustrative task. It separates deterministic checks on actions and service state from quality judgments on generated content, distinguishes infrastructure and judge failures from task failures, and uses controlled interruption and lost-acknowledgement cases to test recovery. It also explains why test state must be reset and variable behavior evaluated across repeated runs.

    The closing section connects the results to regression gates: compare current and candidate versions on the same cases, preserve the versioned inputs and checks, and keep critical execution failures separate from aggregate quality scores. Attendees leave with a failure taxonomy, concrete action/effect assertions and a practical agent-evaluation release checklist. This is an operational evaluation session, not a worker-pool architecture talk or product demonstration.
