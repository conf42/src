# Monitoring is still the one thing nobody automated

A talk at [Conf42 Platform Engineering 2026](https://www.conf42.com/platform2026) by [Eleftheria Batsou](https://www.conf42.com/speaker_Eleftheria_Batsou) (Developer Advocate @ UptimeRobot). Page: https://www.conf42.com/Platform_Engineering_2026_Eleftheria_Batsou_monitoring_automated_nobody

Video: https://www.youtube.com/watch?v=0ZAasoB9Zjw

## Abstract

Your platform team automated the repo scaffold, the pipeline, the secrets, the infrastructure, the dashboards. Then someone ships a service and monitoring gets set up by a human, later, by hand, in a web UI, if anyone remembers. That gap is why so many services run for months with either no monitoring or the wrong monitoring. It isn't a tooling problem so much as a workflow one. Monitoring sits outside the golden path, so it depends on discipline instead of defaults. I work on monitoring, and this talk is about closing that gap from the command line. I'll walk through creating and managing monitors as part of a deploy rather than after it, what belongs in a template versus what genuinely varies per service, and the small operational details that bite you the first time, like which credentials have write permissions and which required flags people always forget. I'll also be honest about where a CLI is the wrong answer, and what monitoring you genuinely can't template because it depends on things your service doesn't own. Useful if you own a platform and want new services to arrive already being watched.
