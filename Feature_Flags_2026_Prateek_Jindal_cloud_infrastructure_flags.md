# Building Self-Healing Cloud Infrastructure with Feature Flags

A talk at [Conf42 Feature Flags 2026](https://www.conf42.com/featureflags2026) by [Prateek Jindal](https://www.conf42.com/speaker_Prateek_Jindal) (Staff Software Engineer @ Confluent Inc). Page: https://www.conf42.com/Feature_Flags_2026_Prateek_Jindal_cloud_infrastructure_flags

Video: https://www.youtube.com/watch?v=gKcoOk6s6BU

## Abstract

Modern cloud infrastructure must remain reliable when services fail, workloads become unstable, dependencies behave unpredictably, or newly introduced changes create operational risk. This session presents a practical approach to building self-healing cloud systems using four core practices: automated failure detection, automated recovery, blast-radius reduction, and operational resilience.  The talk explores how feature flags can support these practices by giving infrastructure teams greater control over how changes are activated, monitored, limited, and reversed. Attendees will learn how teams can use feature flags to gradually enable infrastructure behavior, deactivate unstable functionality, isolate affected workloads, and support faster recovery when monitoring systems detect unexpected conditions.  The session also examines how automated detection and recovery mechanisms can reduce reliance on manual intervention. By combining health signals, recovery workflows, and controlled feature activation, teams can respond more consistently to service disruptions while minimizing the impact on dependent systems.  A key focus will be limiting the blast radius of failures. Feature flags can help restrict changes to selected services, workloads, clusters, or environments, preventing one localized issue from becoming a wider platform disruption.  Designed for cloud engineers, DevOps professionals, SREs, platform engineers, and infrastructure architects, this session provides practical architectural guidance for building cloud systems that detect problems, recover automatically, contain failures, and remain manageable during operational change.
