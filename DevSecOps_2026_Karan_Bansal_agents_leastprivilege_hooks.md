# Hardening AI Coding Agents with Hooks: Enforcing Least Privilege on Autonomous Developers

A talk at [Conf42 DevSecOps 2026](https://www.conf42.com/devsecops2026) by [Karan Bansal](https://www.conf42.com/speaker_Karan_Bansal) (Head of AI @ ArmorCode). Page: https://www.conf42.com/DevSecOps_2026_Karan_Bansal_agents_leastprivilege_hooks

Video: https://www.youtube.com/watch?v=yV_k8zLGuHo

## Abstract

AI coding agents run shell commands, write files, install packages, and spawn subagents: autonomous developers with broad system access. Enforcing least privilege on an agent that needs wide access to be useful is a runtime problem, and it is squarely a DevSecOps one. Sandboxes get disabled because they break real workflows, and system-prompt rules are advisory for a model that wants to finish its task.  This talk presents event-driven hooks as the enforcement layer. Hooks intercept every tool call between the agent's decision and its execution, then allow, deny, or modify it. The hook runs outside the model as a separate process, so prompt injection cannot bypass it. I walk through real blocking scripts (dangerous commands, secret exfiltration, typosquatted installs, agents skip-marking failing tests to fake a green build), map the controls to 6 of the OWASP LLM Top 10, and share benchmarks on keeping synchronous checks under 100ms.  Drawn from an MIT open-source toolkit (481 stars, 1,584 tests) running in production. Demos use Claude Code; the pattern ports to Codex, Copilot, and Cursor.
