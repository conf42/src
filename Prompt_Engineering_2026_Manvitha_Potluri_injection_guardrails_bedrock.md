## Abstract

Most teams protect their LLM applications with a single guardrail: a content filter, a system-prompt instruction, or one managed safety service. It looks fine in a demo. Then someone rephrases an attack, encodes it, or splits it across turns, and it gets through.  This talk shares what I learned building and testing guardrails for LLM and agentic AI systems on AWS Bedrock. I evaluated them against 390 attack prompts across 15 categories, including direct and indirect prompt injection, role-play jailbreaks, encoding and obfuscation tricks, and attempts to trigger destructive actions through an agent's tools.  We'll cover: - Why a single detection layer fails, and which attack categories get past it most easily - A dual-detection pattern that combines a managed guardrail with an independent second check, so each covers the other's blind spots - How to extend that into a layered architecture for AI agents, where catching a harmful action before it executes matters more than catching bad text - The tradeoff between false positives and false negatives, and why blocking too much is a real production failure too - An honest evaluation lesson: my first results file looked clean, but it turned out to contain only API throttling errors, not real model responses. How I caught it, and how to build an evaluation harness that won't fool you the same way.
