# From Prompt Engineering to Agent Engineering: When LLMs Can Take Action

A talk at [Conf42 Platform Engineering 2026](https://www.conf42.com/platform2026) by [Cynthia Akiotu](https://www.conf42.com/speaker_Cynthia_Akiotu) (AI Security & Data Protection Associate Manager @ Accenture). ## Abstract

Prompt engineering started with a relatively simple challenge: how do we get language models to produce better, more consistent answers? But LLMs are no longer just answering prompts. We are connecting them to enterprise data, giving them identities and permissions, equipping them with tools, and enabling them to take actions. As we move from prompt-driven applications to agentic systems, the engineering problem changes with them. In this session, I’ll explore the shift from prompt engineering to agent engineering and what it means for anyone building LLM-powered applications. We’ll follow the journey from Prompt → Context → Identity → Tools → Action → Governance, looking at how each layer introduces new capabilities — and new failure modes. What happens when retrieved context contains malicious instructions? What changes when an agent can invoke an MCP tool or API? How should we think about the identity and permissions behind an agent? And how do we maintain visibility and control once agents move beyond generating text and start interacting with real systems? Drawing on practical experience from building enterprise AI agents and helping organizations secure and assess their agentic systems, I’ll share patterns for designing agents that are useful and capable without giving them unnecessary freedom. Attendees will leave with a practical mental model for evolving their approach from engineering better prompts to engineering the identities, context, tools, permissions, and controls surrounding the agents those prompts now power. Key Takeaways Attendees will learn: * Why prompt engineering alone is no longer enough for agentic AI * How prompts, context, identity, tools, and permissions combine in an agentic system * How tool calling and MCP change the security boundary of an LLM application * Why prompt injection and untrusted context become more consequential when agents can take actions * Practical principles for building controlled, observable, and secure AI agents * How to evolve from thinking only about prompt engineering to thinking about agent engineering
