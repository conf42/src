# Ledger to Lake: Automating Database DevOps for ML in Finance with BigQuery, Liquibase, and Harness CI

A talk at [Conf42 MLOps 2026](https://www.conf42.com/mlops2026) by [Alejandro Mercado](https://www.conf42.com/speaker_Alejandro_Mercado) (DevOps & Cloud Architect @ stealth). Page: https://www.conf42.com/MLOps_2026_Alejandro_Mercado_bigquery_liquibase_harness

## Abstract

In regulated financial institutions, deploying Machine Learning models is often bottlenecked not by algorithms, but by rigid database change management and audit requirements. Traditional MLOps pipelines frequently fail to address the critical "Data DevOps" gap, leading to schema drift, failed deployments, and compliance risks when model features depend on evolving database structures.  This "Tale from the Trenches" session details how we engineered a robust, zero-downtime deployment pipeline for our production ML systems using Google BigQuery, Liquibase, and Harness CI. We moved beyond theoretical MLOps to solve real-world friction: ensuring that every model deployment is intrinsically linked to a versioned, verified database schema change.  Attendees will learn:  The Architecture: How we integrated Liquibase to manage BigQuery schema versioning as code, treating database migrations with the same rigor as model artifacts. The Pipeline: How Harness CI orchestrates the handoff between database migrations and model deployment, implementing automated verification gates that prevent schema-model mismatches. The War Story: A candid look at a critical failure where a silent schema change threatened production model integrity, and how our new pipeline now catches these errors before they reach production.  The Result: How we reduced deployment cycles from weeks to hours while achieving 100% audit compliance for database changes in a highly regulated environment.  This talk is for MLOps engineers, Data Platform leads, and DevOps practitioners struggling to bridge the gap between database operations and machine learning lifecycles in enterprise environments. Leave with actionable patterns for implementing Database DevOps in your own ML pipelines.
