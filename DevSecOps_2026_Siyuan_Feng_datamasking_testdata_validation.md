## Abstract

Data masking validation is straightforward when every source and target row shares a stable primary key. Enterprise systems rarely cooperate. Legacy databases, migrated tables, and append-only logs may lack reliable keys, while creating composite keys across hundreds of millions of rows can be prohibitively expensive.  This session presents an architecture that narrows the problem before performing row-level comparison. The method first intersects sensitive values between source and masked target datasets, isolates only the overlapping candidates, accounts for the different behavior of random and dictionary-based replacement, and generates stable composite identifiers only for the narrowed subset.  This makes it possible to distinguish actual masking failures from legitimate dictionary-replacement collisions without generating keys for the entire dataset.  The session walks through the complete decision tree, SQL-oriented examples, architectural tradeoffs, and important limitations such as duplicate candidates and composite-key stability. Attendees will learn how to design a scalable validation layer that preserves evidence, reduces unnecessary computation, and supports repeatable privacy checks in complex test-data environments.
