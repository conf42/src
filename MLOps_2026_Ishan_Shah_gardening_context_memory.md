# AI Gardening for MLOps: Managing Context, Memory, and Entropy in Agentic Systems

A talk at [Conf42 MLOps 2026](https://www.conf42.com/mlops2026) by [Ishan Shah](https://www.conf42.com/speaker_Ishan_Shah) (Staff Software Engineer @ PayPal). Page: https://www.conf42.com/MLOps_2026_Ishan_Shah_gardening_context_memory

## Abstract

Most AI demos are short. Production MLOps and agentic AI workflows are not.  Long-running systems accumulate instructions, retrieved documents, tool outputs, partial plans, stale assumptions, and memory from prior work. None of that looks like a normal service failure, but it can still change behavior: the system keeps responding, tools keep working, and the workflow slowly becomes harder to reason about because its context has drifted.  This talk introduces AI Gardening as a practical discipline for building and operating agentic engineering systems. We will look at what teams need to design once an agent or LLM workflow moves beyond a single prompt: what context is allowed into a workflow, what should expire, what must be preserved for audit, when memory should be scoped or reset, how to detect contradictory instructions, and how to make working state inspectable during real engineering tasks.  The goal is not to make probabilistic systems pretend to be deterministic. It is to make the operational environment around them maintainable: bounded context windows, explicit memory ownership, reset boundaries, retrieval evaluation, artifact handoffs, and evidence that lets humans understand why the system behaved the way it did.  Attendees will leave with a checklist for more reliable AI workflows: treat context as production input, separate durable knowledge from temporary working state, make memory auditable, design reset paths before drift becomes a failure mode, and give humans a clear way to inspect state instead of trusting a transcript.
