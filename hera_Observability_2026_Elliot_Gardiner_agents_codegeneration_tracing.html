Beyond Token Counts: Observability for AI Coding-Agent Trajectories

Video size:

Abstract

AI coding assistants are increasingly long-running software processes: they search repositories, call tools, modify files, run tests, encounter failures, retry, delegate work to subagents, and eventually produce—or fail to produce—a pull request. Yet most organizations still measure them primarily through token consumption, model latency, and adoption. This talk treats coding agents as an observability problem. We’ll model the full engineering trajectory from task to validated outcome: task → context acquisition → tool use → code edits → tests → retries → pull request → review → outcome We’ll look at how OpenTelemetry-style events can reconstruct these trajectories across tools such as Claude Code and Codex, and derive practical signals including context-acquisition time, failed-test iterations, abandoned work, prompt-to-PR latency, and cost per accepted task. Finally, we’ll build a deliberately simple, explainable trajectory grader that distinguishes a clean one-pass implementation from a session that eventually succeeds after repeated iteration—or never actually satisfies its original acceptance criteria. The goal is not another developer-productivity score. It is evidence you can inspect.
