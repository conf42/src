    Abstract

    Platform engineering is usually discussed in terms of cloud infrastructure, but a large mobile app faces the same problem inside a single binary. On T-Mobile’s T-Life app, which serves 53 million active users, five engineering PODs with more than 50 mobile engineers build account, payments, IoT, and loyalty features. Without a platform layer, cross-module dependencies caused cascading build failures and release bottlenecks. This talk shows how the core app shell was treated as an internal platform with clear contracts for the teams building on it: Versioned interface contracts that let modules evolve independently Independent build pipelines that isolate one team’s failures from the others A modular feature-injection framework as a self-service path for shipping features Governance that balances team autonomy with platform stability Reactive MVI/MVVM state patterns that keep data consistent without tight coupling The approach delivered zero build regression across teams and helps sustain a crash-free session rate above 99.9%. Attendees leave with patterns for building an internal mobile platform that scales with the organization.
