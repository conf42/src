    Abstract

    Modern web applications often accept a fundamental assumption: every meaningful user interaction requires a round trip to the backend. This talk challenges that assumption through a concrete, production-grade case study, building nana.events, a blazing-fast event discovery platform powered by a PHP server and a relational database.

    Despite relying on a traditional stack, the system achieves near zero-latency user experience by restructuring how data is delivered and consumed. Instead of treating the backend as the primary query engine at runtime, the server continuously produces two static JSON artifacts: a comprehensive dataset and a smaller, lightweight subset. These files act as precomputed, optimized views over relational data.

    At runtime, the browser becomes the execution engine. All filtering, searching, and navigation occur client-side, eliminating repeated network calls and dramatically reducing latency. The large JSON file enables full functionality under normal conditions, while the smaller file serves as a resilient fallback under constrained or unstable network conditions.

    This session walks through the architectural decisions behind this approach, including data shaping strategies, trade-offs between freshness and performance, memory considerations in the browser, and techniques for maintaining consistency between relational and static representations. We will also discuss when this model breaks down and how to measure its effectiveness.

    Rather than introducing new infrastructure or exotic technologies, this talk demonstrates how rethinking data flow, shifting computation to the edge, and precomputing aggressively can unlock significant performance gains even in conventional environments.
