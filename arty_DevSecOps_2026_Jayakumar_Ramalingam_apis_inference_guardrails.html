    Abstract

    AI-backed APIs introduce new security and reliability risks because a single request may now trigger model inference, retrieve user context, call internal services, rank personalized content, or invoke downstream tools. Traditional API security controls still matter, but they are not enough when the system includes probabilistic outputs, dynamic context injection, automated decisioning, and fallback behavior inside a latency-sensitive path. This session examines practical DevSecOps patterns for securing AI-backed APIs in production. We will look at threat boundaries around user input, retrieved context, feature pipelines, model calls, authorization, logging, audit trails, rate limiting, prompt or tool misuse, and downstream service access. The focus is not abstract AI risk; it is the engineering work needed to make AI-enabled request flows safer to build, deploy, monitor, and operate. Attendees will leave with a practical checklist: what to validate at API boundaries, where to place authorization checks, what to log and what not to log, how to minimize sensitive data exposure, how to design safer fallback behavior, and which observability signals help detect abuse, degradation, or unsafe model behavior before it becomes an incident.
