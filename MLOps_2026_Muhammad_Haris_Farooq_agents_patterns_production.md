# Running 50+ AI agents in production: the patterns that held up

A talk at [Conf42 MLOps 2026](https://www.conf42.com/mlops2026) by [Muhammad Haris Farooq](https://www.conf42.com/speaker_Muhammad_Haris_Farooq) (AI Engineer (AI Lead) @ Ruby AI). Page: https://www.conf42.com/MLOps_2026_Muhammad_Haris_Farooq_agents_patterns_production

## Abstract

I build and run a platform of 50+ Claude agents on Amazon Bedrock at Ruby, a US AI startup. They research companies and the people in them, and write briefings before sales calls, for real customers every day.  Getting the first agent working was the easy part. This talk is about what comes next: keeping dozens of agents accurate, measurable and affordable once real traffic arrives.  What I'll cover, with real traces and numbers:  Let the AI suggest, let the code decide. Scores, formatting and anything that changes a customer's data stay in normal code. It's cheaper, and you can actually test it. Know when quality drops. Quick code checks on every run, and AI judges on a sample of about 1,500 runs a month. One lesson: a judge that can't see what the agent saw will mark correct answers as wrong. Giving it the tool results took one answer from 0.2 to 0.95. Keep the bill under control. We cut our cost per run by about 75%. A big part was prompt caching, which also breaks without any error: a date in the system prompt or tools in a different order is enough. I'll show how to catch it, including a limit I measured on live Bedrock. Make it fast. Running independent agents in parallel cut the time to research a company from about 32 minutes to 11. You'll leave with a short checklist you can use on your own agents the next day.
