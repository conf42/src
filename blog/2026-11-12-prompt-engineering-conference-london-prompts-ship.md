# Prompt Engineering Conference London treats prompts as production code

Conf42 Blog, 2026-11-12. https://www.conf42.com/blog/2026-11-12-prompt-engineering-conference-london-prompts-ship

In short: Prompt Engineering Conference London, November 26 - Wise, AWS, IBM, Red Buffer and Superagentic AI on releasing, testing and judging prompts. CONF42 = 42% off.

The Prompt Engineering Conference comes to London on November 26, 2026, with three tracks and roughly thirty talks that treat a prompt the way you would treat a config change: versioned, rolled out, tested and occasionally rolled back. Speakers come from Wise, AWS, IBM, Red Buffer, Superagentic AI, Optimizely and Busuu, and **CONF42** gives Conf42 readers **42% off**.

It shares the day, the venue (Everyman Canary Wharf) and the registration page with LLMday London, so one ticket gets you both programmes. This post covers the prompt side.

## A prompt rollout can be an incident

The talk to circle first is **Ritesh Modi (Wise)**, *Prompt Release Engineering*. His abstract describes a 5% rollout of a prompt and model configuration that silently stayed in production for five months. If you have ever left a feature flag at 5% and forgotten it, you already know how that story feels, and the talk is about the release discipline that stops it.

**Emmanuela Opurum (SoftNet Technologies)** comes at the same problem from the architecture side with *Designing Production-Grade Prompt Systems for AI Agents: A Solution Architect's Perspective*: why prompt setups that work in a notebook fall over once they meet production.

## Who writes the next prompt?

**Shashi Jagtap (Superagentic AI)** asks exactly that in *Recursive Prompt Engineering: Who Writes the Next Prompt?*, on agents that generate and inspect prompts at runtime. **Guilherme Santos (Blindsight)** follows the other thread in *Prompt Lawyering. How AI games human requests*, starting from the Tetris-playing AI that learned to pause the game so it could never lose. Specification gaming, now with your system prompt.

**Egor Grositskiy (Beat Saber)** brings an art director's view in *When Prompting Isn't Enough*, where the hard part is defining "better" for creative output at all.

## Judging output you cannot check

Evaluation is the second spine of the programme:

- **Tahreem Rasul (Red Buffer)**, *The Agent Eval Stack: Outcomes, Trajectories, Reliability, and Judges*.
- **Olushola Oladipupo (AWS)**, *Before Your Agent Takes Action: Evaluating Customer-Service AI*, for agents that can change records, not just answer.
- **Oliver Gooding (IFF Research)**, *Evaluating LLM Outputs When Quality is Subjective*, where two experts can legitimately disagree.
- **Peter Fox (IBM)** on regression-testing a virtual assistant's migration from rules to LLM orchestration.

**Aleem Khan** adds a PEC-only session, *Detecting 70 Kinds of Bias with a Model You Own*, on replacing LLM API calls in a real-time news pipeline. The keynotes come from **Coral** and from **Miko Pawlikowski (Reliaburger)**.
