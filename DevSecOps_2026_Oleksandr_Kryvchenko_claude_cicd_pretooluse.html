    Abstract

    Claude Code ships a permissions.deny system in settings.json meant to block agents from touching sensitive files. In practice, deny rules can be silently bypassed - an agent asked to read .env may just read it, permissions notwithstanding. This talk walks through that gap, why it matters once agents run inside CI/CD or with elevated file access, and the practical mitigation: PreToolUse hooks that intercept tool calls before execution and enforce policy in your own code, not the model’s. I’ll cover the settings.json hierarchy (user/project/local), where policy actually lives, what a working hook-based guardrail looks like, and what a pentest of an AI-built or AI-operated app should specifically check for. Attendees leave with a settings.json + hook template they can drop into any Claude Code project today.
