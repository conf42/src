    Abstract

    AI coding tools radically change one part of software delivery: producing code. But when code reaches pull requests and pipelines faster, teams often discover that their real constraints are elsewhere: environments, tests, security controls, reviews, approvals, service ownership, deployment practices, and production feedback. The result is a familiar failure mode: more activity, more work in progress, and not necessarily more value shipped. This talk shows how platform teams can make those constraints visible before AI turns speed into larger queues. We will map the delivery path, identify signals that work is waiting rather than moving, and use platform capabilities—golden paths, paved CI/CD, policy as code, self-service environments, and delivery telemetry—to remove friction at the current constraint. AI is not the enemy; it is a stress test for the delivery system.
