# Who Judges the AI Agent? LLM-as-Judge for Testing Non-Deterministic Code Generation

A talk at [Conf42 AI Agents 2026](https://www.conf42.com/agents2026) by [Liran Yushinsky](https://www.conf42.com/speaker_Liran_Yushinsky) (Automation Rockstar @ JFrog). Page: https://www.conf42.com/AI_Agents_2026_Liran_Yushinsky_testing_judge_codegen

Video: https://www.youtube.com/watch?v=FI0zGAXb1Jk

## Abstract

Testing a deterministic API is straightforward — send input, assert output. Testing an AI agent is a different problem entirely. When your product ships an agentic system that takes natural language and generates executable code through a chain of tool calls, traditional assertions break down fast. Correctness has three dimensions that no single tool can cover alone.  In this talk, Liran Yushinsky, Automation Rockstar at JFrog AppTrust, shows how to built a three-layer evaluation framework for exactly this problem:  Deterministic — validate that AI-generated code compiles and conforms to the expected structure against the real API. LLM-as-judge — grade semantic alignment and completeness using another LLM as the evaluator, scoring output against a golden dataset of 30+ natural language to code reference pairs. Red-team — automatically scan the agent for prompt injection resistance using Garak, blocking any output that bypasses the agent's intended behavior  The result: a CI/CD gate that blocks merges when semantic alignment drops below threshold, syntax validity regresses, or any prompt injection test fails — fully automated, running on every PR that touches the agent's system prompt or tool configuration.  Key Takeaways:  * Why each layer catches failures the other two cannot — and why all three are required  * How to implement LLM-as-judge at scale with Promptfoo and Helicone, including practical scoring thresholds and golden dataset design  * How to wire all three layers into a CI/CD gate that blocks on AI quality regressions, not just unit test failures
