# Prompting Is Not the System: Engineering Context, Contracts and Reliable Agent Behavior

A talk at [Conf42 Prompt Engineering 2026](https://www.conf42.com/prompt2026) by [Emerson Braun](https://www.conf42.com/speaker_Emerson_Braun) (Staff Engineer / Regional Director @ Plan A Technologies). Page: https://www.conf42.com/Prompt_Engineering_2026_Emerson_Braun_contracts_context_agent

Video: https://www.youtube.com/watch?v=xriFNqUxZlM

## Abstract

A prompt can influence a model, but it cannot replace an engineering system. When an agent has access to project context, tools, memory, and production workflows, reliability depends on the contracts around the prompt as much as on the wording inside it.  This talk moves from prompt-centric thinking to context engineering. We will examine a realistic agent workflow and identify where it breaks: incomplete or stale context, instructions that conflict with tool permissions, unstructured model output, retries that repeat side effects, and prompts that grow until nobody understands what the agent is actually allowed to do.  The session presents a practical model for reliable agent behavior:  - treat context as an explicit, versioned input contract; - separate stable policies, task context, retrieved knowledge, and user intent; - define tool schemas, permissions, validation, and failure behavior outside the prompt; - use structured outputs and deterministic handlers for decisions that must be predictable; - let the model reason where ambiguity exists, but keep high-risk actions behind policies and checkpoints; - evaluate complete workflows instead of judging isolated answers; - observe, test, and recover from failures in production.  Using AgentsKit as a concrete example, we will compare a prompt-only implementation with a bounded workflow that combines deterministic logic and model reasoning. The goal is not to eliminate prompts, but to put them in their proper place: one layer in a larger system of context, contracts, tools, evaluation, and operational feedback.  Attendees will leave with a practical checklist for diagnosing whether an agent needs a better prompt, better context, a stronger tool contract, or a different system design altogether.
