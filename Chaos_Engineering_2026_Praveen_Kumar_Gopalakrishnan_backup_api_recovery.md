# Your Backup Is Not Your Recovery: Rebuilding API Trust Without Rebuilding the Breach

A talk at [Conf42 Chaos Engineering 2026](https://www.conf42.com/chaos2026) by [Praveen Kumar Gopalakrishnan](https://www.conf42.com/speaker_Praveen_Kumar_Gopalakrishnan) (Senior Technical Architect @ Salesforce). Page: https://www.conf42.com/Chaos_Engineering_2026_Praveen_Kumar_Gopalakrishnan_backup_api_recovery

## Abstract

Most resilience planning asks one question after an incident: how fast can we get back up? After a cyber incident, that question is dangerous. The fastest restore often reinstates the long-lived credentials, broad service permissions, network-based trust, and undocumented dependencies that made the system fragile in the first place. NIST SP 800-207, SP 800-207A, and SP 800-184 define zero trust and recovery, but leave the transition between them undefined.  This talk presents a five-step method for using the recovery window to reduce fragility rather than restore it. Teams map API dependencies across seven attributes, including privilege, business criticality, and exposure to compromised infrastructure, then contain compromised credentials, introduce an identity-centered API control plane, apply risk-adaptive authorization, and modernize progressively from the highest-risk interfaces.  Instead of a binary allow or deny, which turns every policy decision into a potential outage, authorization supports six graded outcomes: allow, restricted, read-only, step-up authentication, quarantine, and deny. This lets systems degrade gracefully under suspicion instead of failing hard. An enforcement gateway wraps legacy APIs without rewrites, and seven indicators, such as implicit trust paths removed and mean time to revoke access, track progress on a synthetic API dependency graph.  Attendees will leave with a recovery approach that treats every incident as a chance to remove hidden failure paths.
