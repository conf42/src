# Behavioral Regression Testing for LLM Systems: Chaos Engineering for a Dependency You Do Not Control

A talk at [Conf42 Chaos Engineering 2026](https://www.conf42.com/chaos2026) by [Anwar Khan](https://www.conf42.com/speaker_Anwar_Khan) (Senior Staff Software Engineer @ John Deere). Page: https://www.conf42.com/Chaos_Engineering_2026_Anwar_Khan_llm_regression_testing

## Abstract

Chaos engineering assumes you can inject the fault. With a hosted model you cannot. The provider upgrades the model on their schedule, behavior shifts underneath you with no deploy on your side, and the first signal is often a support ticket rather than an alert. The dependency is nondeterministic, it is versioned by someone else, and it fails by being subtly wrong instead of by returning an error.  This talk covers how to build a deliberate practice around that. We start with eval-as-code: a behavioral suite that runs in CI on every prompt change, every retrieval change, and every model swap, with pass thresholds that gate the deploy rather than emailing a report nobody reads. We cover how to pick cases that actually catch regressions, including the adversarial and edge inputs that only show up once you have production traffic to mine.  Then we move to the faults you can inject. Degrade the model tier and see whether quality holds. Return empty or contradictory retrieval and see whether the system says it does not know or invents an answer. Truncate context and watch which instruction gets dropped. Introduce latency on a tool and see whether the orchestration degrades gracefully or stalls. Replay traffic against a candidate model before the provider forces the move.  We finish on drift detection in production: sampling live outputs into the same eval harness, tracking scores as a time series rather than a one-time gate, and alerting on the shape of the distribution rather than on individual failures.  Takeaways: A CI-enforced behavioral regression suite. A catalog of injectable faults for LLM and retrieval systems. Drift detection that catches a silent provider-side change before users do.  Audience: SREs, ML and AI engineers, platform teams. Level: Intermediate to advanced.
