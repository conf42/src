## Abstract

MCP made it trivial to give an LLM hundreds of tools - and quietly catastrophic for your context window. Every pre-loaded tool schema is prompt real estate, and in our production setup, the model was burning 150K tokens "before reading the user's question". Worse than the cost: tool-selection accuracy collapsed under the noise, with the model picking the right tool only 42% of the time.  This talk covers Code Mode, a context engineering technique that replaces MCP's schema dump with typed API stubs the model reads like library code. Same tools, different presentation - and this presentation resulted in: 85% token reduction (150K to 22K), tool-selection accuracy up from 42% to 80%, and fewer round-trips per task.  I'll walk through how we measured the baseline (and why most teams never notice this problem), how typed stubs change what the model actually attends to, the failure modes we hit along the way - stub granularity, stale type signatures, when the model hallucinates methods that "should" exist - and when you should "not" use this pattern. You'll leave with a measurement approach you can run against your own agent the same day, and a simpler alternative if numbers are difficult to comprehend.  Everything shown is from a real production system, not a benchmark.
