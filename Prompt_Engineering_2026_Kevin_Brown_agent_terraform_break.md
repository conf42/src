# Your Agent Can Write Terraform. It Can't Feel What It Breaks.

A talk at [Conf42 Prompt Engineering 2026](https://www.conf42.com/prompt2026) by [Kevin Brown](https://www.conf42.com/speaker_Kevin_Brown) (Founder & CEO @ Cloud World Model). Page: https://www.conf42.com/Prompt_Engineering_2026_Kevin_Brown_agent_terraform_break

Video: https://www.youtube.com/watch?v=QbHUdS0xTDk

## Abstract

Prompt engineering decides what an agent intends. Something else decides what happens when it acts. An agent that can write and apply an infrastructure change has no way to feel that change's cost, latency or failure behavior until it's already live, and the usual guardrail, a sandbox, only covers code. It says nothing about what a workload does at 300 requests per second or what a node failure does to a queue.

This talk is about the missing layer between an agent's plan and the real cloud: a model of what the change will do. I'll simulate one proposed infrastructure change before merge and show the modeled CPU, latency, error rate, cost and resilience, then spend as much time on where the model is wrong as where it's right. I'll label every number as modeled, estimated or a known gap.

You'll leave with a way to give an agent consequences before it has access, and a clearer sense of which infrastructure questions a simulation can answer and which still need a real environment.
