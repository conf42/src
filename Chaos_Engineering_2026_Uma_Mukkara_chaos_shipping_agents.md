# The Agent Ships Faster Than You Can Review: Chaos Engineering Best Practices for Agentic Developers

A talk at [Conf42 Chaos Engineering 2026](https://www.conf42.com/chaos2026) by [Uma Mukkara](https://www.conf42.com/speaker_Uma_Mukkara) (Head of Resilience Testing @ Harness). Page: https://www.conf42.com/Chaos_Engineering_2026_Uma_Mukkara_chaos_shipping_agents

## Abstract

AI agents now ship code faster than any team can review it. The old safety net was a human reading every change. That net has holes. The opportunity isn't to review more. It is to prove more, before the release ships.

This keynote shows how to run resilience testing when the developer is an agent. The order is simple: predict the risk, rank it, prove it with an experiment, and gate the release on the evidence.

You will take away six practices: start from risk, write experiments as hypotheses with probes, gate every environment, let agents draft while humans own policy, test the agents themselves, and feed incidents back into the next scan. We will also cover how AI agents fail: slow models, tool timeouts, silent model swaps and cascading chains.

For platform engineers, SREs and developers who use coding agents.
